## 二、任务书模块与实现映射

### 模块一 · 用户与角色管理
- \`Constants.ROLE_TEACHER = 2\`；\`AuthInterceptor\` 教师边界显式声明
- 登录页三角色单选；\`/api/user/login\` 校验角色与账号实际角色一致
- 管理端新增「新建用户」「修改角色」两个接口与对应交互
- 前端：\`/student\` 学生端、\`/admin\` 管理端；教师登录进学生端并额外可见「实验室占用总览」

### 模块二 · 实验室资源管理
- \`classroom.open_requirement\`（准入门槛文本），教室新增/编辑表单可填
- 学生端教室详情展示开放要求

### 模块三 · 开放时段管理
- 表 \`lab_open_slot\`：classroom_id / start_date / end_date / week_days / open_time / close_time / slot_capacity / status
- 管理端：列表、新增、编辑、删除、按实验室批量生成
- 学生端：\`GET /api/slot/classroom/{id}?date=\` 查询某日生效时段
- 生效判定：status=启用 ∧ start_date ≤ 查询日 ≤ end_date ∧ week_days 命中
- 提交预约时**必须命中**生效时段，否则拒绝

### 模块四 · 预约申请与冲突检测
- 预约实体新增 \`people_count\`
- 规则 1（时间冲突）：\`新开始 < 旧结束 AND 新结束 > 旧开始\`，沿用底版实现
- 规则 2（剩余容量）：**按开放时段累计**已通过预约人数 + 本次 ≤ 时段上限
  - 修复点：早期实现只累加「时间重叠」的预约，而时间重叠已被规则 1 整段拒绝，导致容量校验恒不触发
  - 现口径：与本次预约落在同一开放窗口内的全部已通过预约都计入占用
  - 上限来源：时段 \`slot_capacity\` 优先，回落 \`classroom.capacity\`
- 前端：选人后实时显示「该时段上限 X 人，已预约 Y 人，剩余 Z 人」；超限拦截提交；改日期会重新拉取当日时段

### 模块五 · 审核与使用记录
- 审核沿用底版（含 FOR UPDATE 复查 + 条件更新防并发），追加容量复查
- 新增 \`usage_record\` 表：reservation_id（唯一）/ classroom_id / user_id / use_date / actual_people / use_status(1 正常·2 部分·3 失约) / remark
- 接口：待登记列表、提交登记、批量标记失约、记录查询、Excel 导出
- 取消预约新增 \`reason\` 落库，保留取消原因
- 使用登记前置校验：预约必须已开始，未到时间的预约不可登记

### 模块六 · 数据统计
- 看板新增「实验室实际使用情况」表：登记条数、正常/部分/失约分布、实际人时、实际使用率、失约率
- 实际使用小时 = 窗口内分钟数 × (实际人数 ÷ 预约人数)，失约折算 0
- 失约率 = 失约记录数 ÷ 该实验室区间内已通过预约数
- 概览新增 \`pendingUsageCount\`（待登记）、\`todayActualPeople\`（今日实到）

## 三、验收标准

1. \`mvn test\` 全绿（当前 131 例）
2. \`vite build\` 成功、\`eslint\` 零 error 零 warning
3. 六大模块接口按 \`docs/接口定义清单-V4.0.md\` 全部可达
4. 三角色权限边界可验证：学生不能登记使用、教师不能审核、管理员全通
5. 数据库脚本幂等：\`init_db.sql\` 可重复执行，\`migration_v4.sql\` 用于既有库升级
